## 指标分析

### 1. 多核是否真的生效

是的，当前不是“形式上设了 `-j96`”。

证据：

- `docker top` 可见多个 `qemu-aarch64 + c++` 同时工作
- 编译目标同时分布在：
  - `common/CMakeFiles/common.dir/...`
  - `tools/mtmd/CMakeFiles/mtmd.dir/...`

这说明并发已经从“单个翻译单元”扩展到多个目标的真实并行。

### 2. 为什么仍然慢

因为当前路线本质上仍然是：

- `x86_64` 宿主机
- 通过 `qemu-aarch64` 模拟执行 `arm64` 编译器

即使多核开到 96，仍然会有两个客观代价：

1. `qemu` 指令翻译开销高
2. `llama.cpp` 的 `common + mtmd + models` 翻译单元很多，而且不少文件本身就很重

所以这条路适合作为：

- 服务器上可复现的 `aarch64` 构建方案

但并不是最快方案。理论上更快的路线仍然是：

- 直接使用 `xilinx-zynqmp-common-v2023.1` 的交叉工具链做原生 cross compile
